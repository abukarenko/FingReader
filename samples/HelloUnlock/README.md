# Hello Unlock

Небольшое отдельное приложение WinForms / .NET 10 для проверки разблокировки через Windows Hello на Windows 11. Для используемого desktop interop Microsoft указывает минимальную сборку 22000. Использует текущую учётную запись Windows и уже зарегистрированный в Hello палец; наша база FingReader не требуется.

Системная проверка и передача фокуса выделены в переиспользуемую библиотеку `src/FingReader.WindowsHello`. Это приложение подключает её через ProjectReference. API и инструкция подключения к другим приложениям: `docs/WindowsHello.md` в корне репозитория.

1. Запустите `Запустить.cmd` после сборки.
2. При открытии автоматически появится системный запрос Windows Hello, кнопки разблокировки нет.
3. В системном окне приложите палец к FS80H или используйте PIN.
4. При успешной проверке откроется учебный раздел. При отмене/ошибке доступ остаётся закрыт.
5. «Заблокировать», истечение 60 секунд или блокировка сеанса Windows снова закрывают раздел. Подтверждение запускается автоматически, когда окно приложения активно. В фоне запрос не перехватывает работу; после возвращения в приложение появится Hello. Новый запуск всегда закрыт.

При нажатии «Отмена» запрос не открывается снова по кругу: доступ остаётся закрыт. Для повторной попытки сверните и откройте окно либо переключитесь в другое приложение и вернитесь. Одновременно выполняется только одна проверка.

Приложение не получает отпечаток, PIN, имя или способ подтверждения: Windows возвращает результат проверки. Выбрать исключительно FS80H этим API нельзя. Драйверы и DLL Futronic приложению не нужны; сканер должен быть настроен в Windows Hello.

Используется настольный `UserConsentVerifierInterop.RequestVerificationForWindowAsync` с HWND формы; отсутствие настройки/устройства и запрет политики обрабатываются по возвращённому результату. Открытие раздела разрешено только при `Verified`; устаревший результат после блокировки не принимается.

Перед системным запросом приложение проверяет, что его форма действительно находится на переднем плане. DLL запускает WinRT-запрос в рабочем потоке MTA, сохраняя обработку сообщений HWND в потоке интерфейса. Если окно неактивно, запрос ожидает возвращения пользователя в приложение.

В течение первых пяти секунд ожидается ровно одно новое видимое окно системного CredentialUIBroker.exe: проверяются полный путь к EXE в системной папке Windows и текущий сеанс входа; уже существовавшие окна исключаются. Разрешение на передний план передаётся конкретному PID через AllowSetForegroundWindow, затем вызывается SetForegroundWindow. После успешной передачи либо трёх неудачных попыток наблюдение прекращается. Если пользователь переключился в другое приложение, фокус не отбирается. Поиск по локализованному заголовку, ASFW_ANY, TOPMOST, AttachThreadInput и изменение системных ограничений фокуса не используются. Определение нового окна — ограниченная эвристика: если окно брокера переиспользовано или кандидатов несколько, приложение не выбирает окно наугад.

В версии с DLL временная файловая диагностика удалена. Библиотека не пишет журнал. Самопроверка приложения явно создаёт только `self-test-result.txt` при запуске с `--self-test`.

Это демонстрация подтверждения текущего пользователя, а не шифрование файлов и не серверная авторизация. Настоящие секреты здесь не хранятся. Для защиты реальных данных нужны отдельное безопасное хранение и проверка прав. Параметры входа Windows приложение не меняет.

Сборка из корня репозитория, каждая команда PowerShell — одна строка:

```powershell
dotnet publish .\samples\HelloUnlock\HelloUnlock.csproj -c Release -r win-x64 --self-contained true -o .\samples\HelloUnlock\publish
```

```powershell
& '.\samples\HelloUnlock\publish\HelloUnlock.exe'
```

Самопроверка переходов доступа (без сканера и системного запроса):

```powershell
Start-Process '.\samples\HelloUnlock\publish\HelloUnlock.exe' -ArgumentList '--self-test' -Wait
```

При успехе рядом с EXE появляется `self-test-result.txt`. Обычный режим не сохраняет результаты аутентификации на диск.
